## 2. Reservation is not additional memory

| Class | Quantity / accounting rule |
|---|---|
| Linux System RAM aperture |40MiB `[0x81800000,0x84000000)`. Do not recover capacity by counting outside this declared aperture. |
| CMA reservation |16MiB `[0x82800000,0x83800000)`, **inside**40MiB. Reservation designates eligible pages; it is not another16MiB nor16MiB already consumed. Compiled default CMA is0; the volatile boot argument is essential. |
| Managed memory / kernel reservations |Dated MemTotal33144KiB is7816KiB below the40MiB aperture. This difference is not spare media capacity or a measured per-subsystem allocation breakdown. Kernel image, metadata and reserved pages are already represented by the actual managed/free observations; do not subtract their whole sizes again from sampled free. |
| CMA occupied versus live owners |Dated free9216 means occupied7168KiB, **not** a measured7168KiB ISP allocation. Known requested ISP6160KiB does not explain/prove placement of every occupied page. Neither all occupied CMA migrates nor none migrates is established by that subtraction. |
| Atomic coherent pool |K76 `arch/arm/mm/dma-mapping.c:185–235` defaults256KiB and allocates it from CMA when an area exists, on successful initialization. Boot-lifetime fixed cost; verify actual override/init result before credit. It is not an extra per-encode allocation and must not be added twice to a sampled occupied-CMA total. |
| Allocator alignment |4KiB pages; coherent requests are PAGE_ALIGN'd. ARM coherent CMA path uses exact page count and `get_order` alignment capped by CONFIG_CMA_ALIGNMENT8:2/4MiB requests require1MiB starting alignment, table16KiB alignment, stats12KiB request16KiB alignment, aux64KiB alignment. Alignment gaps/fragmentation are not guaranteed usable capacity. No automatic power-of-two rounding of every12KiB request to16KiB payload is assumed. |

Sources: final config; K76 `arch/arm/mm/dma-mapping.c:391–418,533–599` and
`kernel/dma/contiguous.c:316–322`. GFP_KERNEL coherent allocations select the CMA
allocator when the relevant area exists; allocation failure is not a license to
assume fallback/compaction will succeed. Heap/static CPU storage uses a different
API but may borrow movable CMA pages: charge CPU globally and conservatively
forecast its Normal placement/evacuation, rather than calling every CPU page
physically non-CMA without evidence.

Current queue code allocates/programs all four slots, enables both mask banks

```text
A >= CPU_unpaid + codec_unpaid + H512 + R1024
N_above_W >= CPU_unpaid + H512 + R1024 + M_future
```

Overlay ordering supported by the byte-matched76 codec source:

1. Under encoder mutex/owner checks, copy **all1382400 main bytes** into private
   `enc.input` before programming only kernel-owned DMA addresses.
2. ASIC completion →bounded stop/reset retirement→DMA read barrier→full guards/
   status/length checks→copy≤1MiB encoded output into user destination. No later
   user-raw read in the transaction; no alias prohibition in this synchronous ABI.
3. v6 full1728000 raw CRC is before ioctl; raw-valid is revoked **before** the call,
   even for partial EFAULT. Postencode raw storage is a NAL loan, never raw pixels.
4. Copy NAL to onehub→compare source/pre CRC→release producer loan→acquire hub_n→
   produce n+1 into raw overlay→recheck oldhub CRC→bounded send of n using real
   next timestamp→release all old leases→publish n+1. No next while producer loan
   is held; no acquired-hub overwrite; terminal AU is retired whole, not exported
   with guessed duration. Source/DMA/clock/CRC uncertainty retains backing.
