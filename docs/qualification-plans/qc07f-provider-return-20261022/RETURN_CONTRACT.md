# Strict pre-memory custody return — contract before code

2026-10-22; RP-07/09, STREAM-04/07 source-only dependency. No runtime acceptance.

## Scope / trusted bootstrap

Only a healthy native COMMITTED owner before any memory/session/guard controls,
activation, local capture/reference-job history, CPU loan/backing or close attempt
may return descriptions. ACTIVE, post-memory nonactivated abort, partial failed
adoption/HOLD and recovery remain outside this API. No normal END/ACK proof is
invented. Exact bootstrap boot/image/provider association, prior DMA-history
admission, sole stable open descriptions/no aliases and absence of competing
dispatch/I/O/FD changes/reentry remain independent trusted prerequisites. BIND
NONE, O_RDWR and metadata do not establish them or give permission to close/free.

All calls, slots and objects are serialized, stable and disjoint, including all
four destination int objects versus native private metadata/owned buffers/loans.
Destinations must each be -1 and distinct objects. Numeric FD distinction alone
does not prove distinct open descriptions. Bootstrap may not perform I/O on newly
populated destinations until this call returns, even when an earlier role has
already moved. No new locking/reference/guardian framework or retention owner.

## Source-history admission

Refuse observed uncertainty/HOLD/stop/source-clock failure first, retaining it.
Then require actual COMMITTED role ownership with all three active slots present,
staging records EMPTY/fd=-1 and no staged sensor; no armed receipt, source/file/
capture generation or sequence, stream/reference/ownership history, raw-valid/
NAL/timing/output/private expected loan, resident/parked backing, close diagnostic,
legacy/temporary role. Memory runtime is uninitialized with no session, callbacks,
observations or paid ledger records. Actual watchdog must be UNKNOWN, with no
session start/deadline, phase begin, control phase or progress; UNKNOWN is not
unarmed/unstarted hardware. Opening already started it. Metadata-clock observations
do not create a session seal or service it.

These are local source-history facts. Observational global encoder history/live
bytes and telemetry counters may describe earlier provider history; they are
retained, never recast as absence of all prior DMA or a newly unique grant.

## Observe before moving; explicit nonatomic result

Record one real monotonic return start. Reuse actual frame/per-open encoder/global
lifetime observation before moving, along with watchdog device/node/mode/CLOEXEC
metadata and clock checks. Fresh frame NONE/gen0 and encoder NONE/clean expected
session are mandatory; old76 query88 support is not guessed. Keep latest valid
snapshots before refusing valid contradictory observations. Failed/partial replies
cannot replace a valid snapshot.

Mark RETURNING after successful preflight. Reobserve sensor metadata then move
actual sensor -> destination and invalidate the native slot. Reobserve frame node/
BIND/NONE/expected source+file, then move the actual frame. Reobserve encoder node/
per-open identity/NONE/fault facts, then move the actual encoder. Original global
facts were observed before all moves; under serialized/no-competing-dispatch and
no recipient I/O until return, no encoder job is introduced between observations.
All moves use stable actual native slots, never stack-only owners or helper
snapshot metadata claiming duplicate ownership. Frozen custody helpers stay exact.

Check the same original <2s return interval at admission and before each move.
Move the actual UNKNOWN watchdog description LAST with separately named
UNKNOWN-bootstrap observe/return functions, requiring the same unchanged identity
and no session/control history. They perform only real clock/GET metadata, never
ioctl control/disable/enable/ping, V/write/close, I2C selector, ARM/job/END/ACK/reset.
The source watchdog owner becomes terminal returned-UNKNOWN/fd=-1, not DISABLED.
The recipient's FD is explicitly UNKNOWN, may still be active with unknown current
timeout, and must be retained/serviced/recovered under bootstrap's separately
admitted policy. Returned FD is NOT permission to close, disarm or claim recovery.

Pre/post time checks cannot preempt a blocking syscall or guarantee the unknown
hardware timeout will not expire during handoff. No finite-wait, timer headroom,
electrical-stop or armed-recovery proof follows; bootstrap must admit this
control-free handoff/recovery policy before calling. Expired/unknown/backward time
or failed metadata after earlier moves stops with HOLD, no repair or servicing.

Nonzero return does not undo earlier transfers: each populated destination owns
that actual description, and the corresponding native slot is -1. Remaining actual
native FDs stay owned on HOLD; snapshots/expected identities remain. Bootstrap must
retain its returned FDs and the actual native process for any remaining owners.
No retry, rollback, cleanup, close/error-FD retry or destructor.

## Terminal success and unchanged normal path

Do not reset native_initialized, storage/opt-in, snapshots or accounting to permit
restart. Returned/returning phases refuse subsequent provider/effect/setup/take
paths; reinit remains forbidden and cannot clear terminal history/uncertainty.
This is not normal sensor/encoder retirement or post-memory cancellation.
