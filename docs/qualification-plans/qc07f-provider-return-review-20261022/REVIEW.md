## Actual nonatomic ownership and partial failure

| Completed move | Actual ownership if a later boundary fails |
|---|---|
| None | Native retains all four descriptions; destinations remain=-1. |
| Sensor (:76) | Sensor destination owns actual FD; native continuous_sensor=-1; frame/encoder/watchdog stay native. |
| Frame (:79) | Sensor/frame destinations own actual FDs; native slots=-1; encoder/watchdog stay native. |
| Encoder (:84) | Three provider destinations own actual FDs; native provider slots=-1; actual watchdog remains native on final observation failure. |
| UNKNOWN watchdog (:85–88) | All four destinations own actual FDs; all native FD slots=-1; source phase RETURNED. A final observed cancellation can still return failure/fence without undoing any transfer. |

All moves are direct destination assignment followed by native-slot invalidation,
not copies of helper metadata pretending to own an FD. Their short sequential
duplicate numeric records rely on the serialization/disjoint-storage contract;
they are not concurrent shared ownership or an atomic transaction. There is no
stack-only returning owner, open/dup/close, rollback, destructor or retry. On
partial failure, populated recipients retain earlier transfers while only actual
remaining native descriptions are held. Returning nonzero says neither "native
owns all" nor "everything returned". Caller records/returned FDs and the real
process for remaining owners must survive.

The post-sensor frame observer does not call all-role provider_shape. After frame
moves, encoder observation checks only the still-owned encoder (return:80–83),
not already-invalidated source slots. Original global facts were required before
all moves; trusted no-competing-dispatch/no-recipient-I/O prevents an intervening
encoder job. Latest valid expected snapshots remain stable on failure; no fake
ACTIVE/END/ACK/DMA drain is used to justify handback.

Final cancellation after all four moves calls fence, which can mark the watchdog
metadata HOLD even though fd=-1; it does **not** regain an actual description.
provider_hold preserves source RETURNED history (observe:6–10). Diagnostics and
recipient slots correctly continue to identify what was actually transferred.

## Separate UNKNOWN watchdog handoff

New qw_owner_unknown_bootstrap_observe/return_unknown_bootstrap (:128–145) are
distinct from DISABLED give-back (:122–127). They require UNKNOWN, unsealed/no
phase/progress and current saved device/node/mode/CLOEXEC character descriptor,
then move the actual watchdog **last**. Success invalidates source fd and sets
QW_RETURNED_UNKNOWN while preserving metadata; it does not memset to EMPTY or
manufacture DISABLED. Any earlier failure retains the actual remaining FD on HOLD.

The new bodies call clock/GET metadata only: no watchdog ioctl/keepalive/timeout,
enable/disable, V/write/close, reset or service. Preopen already started hardware.
UNKNOWN may be running at an unknown current timeout: not unstarted, unarmed,
stopped, known-armed recovery or permission to close. Bootstrap must independently
admit and retain/service/recover this control-free handoff under its own policy.
Queries may block past that unknown timeout; <2s source checks are not hardware
headroom or native handoff qualification.
